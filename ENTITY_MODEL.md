## Entity Descriptions

### Enumerations (Enums.cs)

#### CardScheme
Card payment networks recognized by the system:
- `Unknown` (0) - Unrecognized scheme
- `Visa` (1) - Visa cards
- `Mastercard` (2) - Mastercard and Maestro
- `AmericanExpress` (3) - American Express
- `DinersClub` (4) - Diners Club

#### ProductType
Type of card product:
- `Unknown` (0)
- `Consumer` (1) - Personal consumer cards (subject to interchange caps)
- `Commercial` (2) - Business/corporate cards
- `Prepaid` (3) - Prepaid card products

#### FundingType
How the card is funded:
- `Unknown` (0)
- `Credit` (1) - Credit-based
- `Debit` (2) - Debit/immediate withdrawal

#### RegionType
Geographic region for fee/regulation purposes:
- `Unknown` (0) - Cannot determine region
- `Domestic` (1) - Same country as acquirer/issuer
- `IntraEEA` (2) - Within European Economic Area (subject to interchange caps)
- `InterRegional` (3) - Outside EEA (no interchange caps)

### ApplicationUser

Extends ASP.NET Core Identity's `IdentityUser`.

**Purpose**: Manage system users and roles (Admin, Viewer)

**Key Properties**:
- `Id` (from IdentityUser) - Unique user identifier (GUID string)
- `UserName` (from IdentityUser) - Login username
- `Email` (from IdentityUser) - User email address
- `FullName` - Display name for reports
- `IsActive` - Whether account is enabled
- `CreatedAt` - Account creation timestamp
- `UpdatedAt` - Last modification timestamp
- `LastLoginAt` - Timestamp of the most recent successful sign-in
- `Notes` - Internal notes (not shown to users)

**Database Table**: `AspNetUsers` (generated by Identity)

**Relationships**:
- `AuditEntries` - audit rows produced by this user (`AuditEntry.PerformedByUserId`)
- `Imports` - bulk imports performed by this user (`ImportHistory.ImportedByUserId`)

Both use `OnDelete(SetNull)` so history survives if the user account is removed.

**Notes**:
- Configured via ServiceExtensions in Program.cs
- Extend with additional properties as needed (department, branch, etc.)
- Password policy: 8+ chars, requires digit + special character

---

### ApplicationRole

Extends ASP.NET Core Identity's `IdentityRole`.

**Purpose**: Named permission sets applied via `[Authorize(Roles = ...)]`

**Key Properties**:
- `Id` / `Name` / `NormalizedName` (from IdentityRole)
- `Description` - what the role is allowed to do
- `CreatedAt` - when the role was created

**Database Table**: `AspNetRoles` (generated by Identity)

**Seeded Roles** (via `HasData`, fixed Ids so the seed is stable across migrations):

| Role | Access |
|---|---|
| `Admin` | Manage BIN ranges, commission rules, users and imports |
| `Viewer` | Read-only: browse BIN ranges, rules and audit history |

Use the `AppRoles` constants (`AppRoles.Admin`, `AppRoles.Viewer`) rather than string
literals so authorization attributes stay in sync with the seeded rows.

**Bootstrap admin**: `DbInitializer` applies pending migrations, ensures the roles exist,
and creates the first admin account from configuration:

```
Seed:AdminEmail
Seed:AdminPassword
```

Supply these via user secrets or environment variables — no credential is committed to the
repository. If either is missing, admin seeding is skipped with a warning.

### Region

Geographic regions for determining fee rules and compliance requirements.

**Purpose**: Group countries for regulation and fee calculation (e.g., EEA vs non-EEA cards have different interchange fee caps)

**Key Properties**:
- `Id` - Primary key
- `Type` - RegionType enum (Domestic, IntraEEA, InterRegional, Unknown)
- `Name` - Display name (e.g., "Intra-EEA")
- `Description` - Explanation of region characteristics

**Database Table**: `Regions`

**Relationships**:
- One Region → Many Countries
- One Region → Many CommissionRules

**Seeded Data** (4 regions):
```
Id=1: Domestic           - Same country transactions
Id=2: Intra-EEA          - Within European Economic Area
Id=3: Inter-Regional     - Outside EEA (e.g., USA, UK post-Brexit, Asia)
Id=4: Unknown            - Could not determine region
```

**Indexes**: Unique on `Type` (each region type appears once)

---

### Country

ISO country codes mapped to regions for BIN classification.

**Purpose**: Map issuing country to region, used when classifying BINs

**Key Properties**:
- `Id` - Primary key
- `Code` - ISO 3166-1 alpha-2 code (e.g., "BG", "US", "GB") - Fixed 2 characters
- `Name` - Full country name
- `RegionId` - Foreign key to Region
- `CreatedAt` - Record creation timestamp
- `UpdatedAt` - Last modification timestamp

**Database Table**: `Countries`

**Relationships**:
- Many Countries → One Region
- Many BINs → One Country (via issuing country)

**Seeded Data** (33 countries):
- Bulgaria (Domestic)
- EEA members: Austria, Belgium, Croatia, Cyprus, Czech Republic, Denmark, Estonia, Finland, France, Germany, Greece, Hungary, Ireland, Italy, Latvia, Lithuania, Luxembourg, Malta, Netherlands, Poland, Portugal, Romania, Slovakia, Slovenia, Spain, Sweden
- Post-Brexit UK (InterRegional)
- Non-EEA examples: USA, Canada, Japan, China, India

**Indexes**: Unique on `Code`

**Constraints**: Foreign key to Region with restrict delete (prevent orphaned countries)

### BinRange

Bank Identification Number (BIN) records - the core data for card classification.

**Purpose**: Store card scheme and product information indexed by BIN prefix for fast lookup

**Key Properties**:
- `Id` - Primary key
- `Prefix` - BIN prefix (6-8 digits) - Unique, indexed
- `Scheme` - CardScheme enum (Visa, Mastercard, Amex, Diners, Unknown)
- `ProductType` - ProductType enum (Consumer, Commercial, Prepaid, Unknown)
- `FundingType` - FundingType enum (Credit, Debit, Unknown)
- `CountryId` - Foreign key to Country (issuing country)
- `CreatedAt` - Record creation timestamp (default: current time)
- `UpdatedAt` - Last modification timestamp (default: current time)
- `LastModifiedBy` - User ID who last modified (for audit trail)

**Database Table**: `BinRanges`

**Relationships**:
- Many BINs → One Country

**Indexes**:
- Unique on `Prefix` (no duplicate prefixes)
- `(Prefix, Scheme)` for scheme detection lookups

**Validation** (at service layer):
- Prefix must be 6-8 digits (numeric only)
- No duplicate prefixes allowed

**Constraints**: Foreign key to Country with restrict delete

**Example Records**:
```
456123  | Mastercard | Consumer  | Credit | Bulgaria (Country 1)
451234  | Mastercard | Commercial| Debit  | Bulgaria (Country 1)
412345  | Visa       | Consumer  | Debit  | USA (Country 29)
```

**Performance Notes**:
- The prefix index enables longest-prefix-match lookups (6→7→8 digit search)
- Index critical for classification performance
- No BIN data is hard-coded; all loaded from database

### CommissionRule

Fee calculation rules for transactions based on card attributes.

**Purpose**: Store configurable pricing rules: percentage + fixed amount + minimum fee

**Key Properties**:
- `Id` - Primary key
- `Scheme` - CardScheme? (nullable = wildcard for "any scheme")
- `ProductType` - ProductType? (nullable = wildcard for "any product")
- `RegionId` - int? (nullable = wildcard for "any region")
- `PercentageRate` - decimal(5,4) - e.g., 0.85 for 0.85% (supports 99.9999% max)
- `FixedAmount` - decimal(10,4) - e.g., 0.12 (€0.12, BGN 0.12, etc.)
- `Currency` - 3-char code (e.g., "EUR", "BGN")
- `MinimumFee` - decimal(10,4) - e.g., 0.20 (lowest fee charged even if calculation is lower)
- `ValidFrom` - DateTime (inclusive start date)
- `ValidTo` - DateTime? (nullable = open-ended/no expiration)
- `IsActive` - bool (enable/disable without deleting)
- `Description` - Optional rule description
- `CreatedAt` - Record creation timestamp
- `UpdatedAt` - Last modification timestamp
- `LastModifiedBy` - User ID who last modified

**Database Table**: `CommissionRules`

**Relationships**:
- Many Rules → One Region (optional, for wildcards)

**Indexes**:
- `(Scheme, ProductType, RegionId, ValidFrom, ValidTo)` for rule resolution lookups
- `IsActive` for quick filtering

**Example Rules** (realistic tariffs):
```
Scheme: Mastercard   | Product: Consumer   | Region: IntraEEA
  → 0.85% + €0.12, minimum €0.20
  (Interchange cap: 0.3% for Consumer EU, rest is bank fee)

Scheme: Any          | Product: Commercial | Region: IntraEEA
  → 0.95% + €0.15, minimum €0.30
  (Commercial not subject to interchange caps)

Scheme: Any          | Product: Any        | Region: InterRegional
  → 2.00% + €0.25, minimum €0.50
  (No caps outside EEA)
```

**Wildcards** (Specificity Ranking):
Exact > Exact > Exact (highest priority)
Exact > Exact > Wildcard
Exact > Wildcard > Exact
...continuing to...
Wildcard > Wildcard > Wildcard (lowest priority)

**Validation** (enforced):
- Percentage ≥ 0
- Fixed amount ≥ 0
- Minimum fee ≥ 0
- ValidFrom ≤ ValidTo (if both set)
- No overlapping validity periods for same (Scheme, ProductType, Region) combination

### AuditEntry

Immutable audit trail of all configuration changes for compliance.

**Purpose**: Track who changed what, when, and why (non-repudiation)

**Key Properties**:
- `Id` - Primary key
- `EntityType` - String (e.g., "BinRange", "CommissionRule", "Country")
- `EntityId` - ID of the entity that changed
- `Action` - AuditAction enum (Created, Updated, Deleted, Deactivated, Imported)
- `UserId` - User ID who made the change
- `UserName` - Username (for easier reading than just ID)
- `OldValues` - JSON snapshot of previous state (for updates/deletes)
- `NewValues` - JSON snapshot of new state (for creates/updates)
- `ChangedProperties` - Comma-separated list of property names that changed
- `ChangeReason` - Optional description of why the change was made
- `Timestamp` - When the change occurred (default: current time)
- `ClientInfo` - IP address or client identifier

**Database Table**: `AuditEntries`

**Constraints**:
- **NO DELETE OR UPDATE** - Audit records are immutable for compliance
- Accessible only to Admin/Compliance users

**Indexes**:
- `(EntityType, Timestamp)` for browsing change history
- `UserId` for user activity reports

**Example Entries**:
```
Action=Updated, EntityType=CommissionRule, EntityId=5
  OldValues: {"PercentageRate":0.95,"IsActive":true}
  NewValues: {"PercentageRate":0.92,"IsActive":true}
  ChangedProperties: "PercentageRate"
  UserId: "user-id-123"
  Timestamp: 2026-08-01 14:32:45 UTC

Action=Imported, EntityType=BinRange
  NewValues: {"RowsImported":1234,"RowsUpdated":456,"RowsRejected":12,"FileName":"mastercard_bins_20260801.csv"}
  Timestamp: 2026-08-01 09:15:00 UTC
```

## Adding New Entities

### Step 1: Create Entity Class

Create file in `BinTool.Core/Entities/YourEntity.cs`:

```csharp
namespace BinTool.Core.Entities;

public class YourEntity
{
    public int Id { get; set; }
    
    public string Name { get; set; } = string.Empty;
    
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    
    // Relationships
    public int? RelatedEntityId { get; set; }
    public RelatedEntity? RelatedEntity { get; set; }
}
```

### Step 2: Configure in AppDbContext

Add to `OnModelCreating` in `AppDbContext.cs`:

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    base.OnModelCreating(modelBuilder);
    
    // ... other configurations ...
    
    ConfigureYourEntity(modelBuilder);
}

private static void ConfigureYourEntity(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<YourEntity>(entity =>
    {
        entity.HasKey(e => e.Id);
        
        entity.Property(e => e.Name)
            .IsRequired()
            .HasMaxLength(100);
        
        entity.ToTable("YourEntities");
    });
}
```

### Step 3: Add DbSet

Add to `AppDbContext.cs`:

```csharp
public DbSet<YourEntity> YourEntities { get; set; }
```

### Step 4: Create Migration

```bash
dotnet ef migrations add Add_YourEntity --project BinTool.Infrastructure --startup-project BinTool.Api
dotnet ef database update --project BinTool.Infrastructure --startup-project BinTool.Api
```

## Important Notes

1. **No Hard-Coded Data**: All BIN values, countries, commission rates are stored in database as data, never in code.

2. **No Full Card Numbers**: The system only works with BIN prefixes (max 8 digits), never stores or logs complete card numbers.

3. **Nullable Enums for Wildcards**: Use `CardScheme?` to allow null for wildcard rules where any scheme matches.

4. **Temporal Data**: All entities track `CreatedAt` and `UpdatedAt` for audit purposes.

5. **Decimal Precision**: Use `decimal` with `HasPrecision()` for monetary values to avoid floating-point errors.

6. **Foreign Key Constraints**: Set to `Restrict` to prevent accidental deletion of referenced data.

7. **Soft Delete**: Use `IsActive` flag instead of hard deletes for reversibility (except audit entries).

## Diagram: Fee Calculation Flow

```
User Input: BIN + Amount
    ↓
BIN Classification:
  - Scheme Detection (Visa, MC, Amex, Diners)
  - BIN Lookup (6-digit → 7-digit → 8-digit prefix match)
  → Classification Result (Scheme, ProductType, FundingType, Region)
    ↓
Rule Resolution:
  - Find all matching CommissionRules for (Scheme?, ProductType?, Region?)
  - Sort by specificity (most specific wins)
  - Filter by ValidFrom/ValidTo and IsActive
  → Applicable Rule
    ↓
Fee Calculation:
  fee = (Amount × PercentageRate) + FixedAmount
  fee = MAX(fee, MinimumFee)
    ↓
Result to User: Classification + Applied Rule + Calculated Fee
```
